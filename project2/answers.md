Part 1.1: -pbkdf2 tells OpenSSL to use PBKDF2 to get the encryption key. It requieres it because AES uses a 256-bit  encryption key, but when having a passphrase we usually make it just simple text (for example, mine was the name of my cat), so, to convert the passphrase into the key, we need -pbkdf2.
Part 1.2: The checksums are different because each encryption uses a different initialazation vector since in AES the IV is randomly generated every time we create a new encription, resulting in different encrypted texts and, as such, different checksums. If the two encrypted files were identical, it would mean the IV used for both files was the same, meaning that an attacker could compare the encrypted text and use how often the characters appear to try and decypher the cypher. Using different IVs for each encryption makes this impossible.
Part 1.3:ECB produces 3 distinct blocks, CBC produces 37 distinct blocks. ECB leaked leaked the unencrypted text, since the same uncencrypted text produced the same encrypted text, allowing an attacker to determine which blocks were identical and use that to try and decypher the contents. To an attacker who never learns my key, they cannot determine the content of the text, but it can determine where it contains the same content and where it repeats. The question I would ask is which encryption mode is being used.
Part 2.2: SHA-256 hash does not protect my collegue because the hash is not secret. An HMAC uses both the file and a secret key to make an authetication tag. With SHA, an attacker can read the file if it was sent without encryption, modify and/or change the file. With HMAC, the attacker can modify the file, but cannot create a valid HMAC, so it cannot guarnatee that the recipient will not realize that the file was altered.

Part 4.2: The public key packet contains the information needed to encrypt a session key for the recipient's RSA public key. The encrypted data packet contains the actual message encrypted with the symmetric session key. GPG uses this approach because RSA is a very slow process, so it is inefficient for encypting entire messages. This construction is called hybrid encryption.
Part 4.3: The sender's private key is used for signing. The sender's public key is used for verifying. The recipient's public key is used for encryption. The recipient's private key is used for decryption. One security property provided by signing that encryption does not include is integrity, as it can check that the files have not been altered in transit.
Part 5: The much smaller Ed25519 key is not necessarily the weaker key since it uses its own specific type of encryption, which allows smaller keys than RSA ones to still be harder to solve for any given size, so even a smaller key can be harder to solve than a longer RSA key.
